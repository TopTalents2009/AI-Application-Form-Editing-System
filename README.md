# AI Application Form Editing System

**版本 2.7.2** · 申报书智能修改系统（FastAPI）

上传已填写的申报书与区域修改意见，系统自动识别申报书模板（QM 启明 Word / HJ 火炬 Word·Excel），由 **Gemini 单模型**按章生成编辑计划，**人工逐条核对确认后再按原版式写回源文件**（Word 保持表格单元格结构，Excel 保留格式与宏）。生成计划时检索外部只读人才库 / 企业库补齐空缺字段；意见点名缺护照、学历证明、论文全文、证件照、电子签等附件时，**先查本机「附件」目录（按申报书编号），找不到再到人才库，仍没有则在企业微信聊天记录中按编号/姓名检索群文件**，并给出下载链接；库内没有论文文件时按人才编号查论文系统，无档或无 PDF 则按作者检索并构建后再拉取。护照扫描件、学历证明、工作经历证明（含证明上的起止时间、入职/离职日期）等无法写入申报书正文的事项，会单独产出 **任务清单.docx**。意见点名缺项目证明时：先查人才库附件包 → 未命中则 CodeBuddy 无头联网检索 → 仍没有则调用生成 API（签发单位为来华前工作单位，不用申报企业；`projectProof.generate` 为模板，需自行填写）。内置 MySQL 账号体系：登录后才能使用，普通用户只能看到自己提交的任务，管理员拥有后台控制台。

仓库：https://github.com/TopTalents2009/AI-Application-Form-Editing-System

## 快速开始

1. Python 3.10+（推荐 conda 环境 `work`）
2. `pip install -r requirements.txt`
3. 复制 `config.example.json` 为 `config.json`，填入密钥（见下节）
4. 双击 `start.cmd`，或 `python run.py`
5. 浏览器打开 http://127.0.0.1:3777
6. 首次启动自动建库并创建初始管理员 `admin / Admin@123456`，**请立即登录后台修改密码**；普通用户在注册页自行注册

`config.json` / `config.default.json` 含密钥，**不要提交到仓库**。运行时目录 `tasks/`、`batches/`、`client_inbox/` 含申报书原文，已列入 `.gitignore`。

`start.cmd` 只会结束占用 3777/3778 的 **python / uvicorn**，不会杀 `svchost`。若 3777 被 Windows 端口转发占用，会改用 3778，可用管理员运行 `fix_portproxy.cmd` 恢复 3777。

> 模板文件 `QM.docx` / `HJ.docx` 放在项目根目录，用于申报书模板比对；文件缺失时退回到内置结构关键词判定，不影响使用。

## 配置

复制示例后按项填写。占位符 `填入` 视为未配置。

| 块 | 作用 |
|----|------|
| `geminiApiKey` 与 `models` 中 Gemini 项 | **Gemini**（12ai，`gemini-3.7-flash`，流式，单次 300 秒）：**生产管线唯一出计划 / 分类模型**（思考中度，温度 0.1） |
| 顶层 `baseUrl` / `apiKey` / `model` / `reasoningEffort` | **Grok** 网关（默认 `grok-4.6`）：仅供管理后台配置与连通性测试，用户端不展示、不参与出计划 |
| `doubaoApiKey` 与 `models` 中火山项 | **火山方舟**（`doubao-seed-2-0-mini-260428`）：同上，保留给管理后台，管线不再调用 |
| `pool` | 汪伦人才库 / 企业库只读接口（`X-API-KEY`，前缀 `/api/external-read/v1`，可带 `allowed_modes` 限制 `QM` / `HJ`） |
| `papers` | 科研成果附件导出 API（`X-Api-Key`，前缀 `/api/v1`，默认局域网 `http://192.168.2.62:8000`） |
| `projectProof` | 项目证明补缺：`codebuddy` 无头联网检索；`generate` 为生成 API 模板（`baseUrl` / `apiKey` / `path` / `headers` / `body` 留空处填 `填入`，占位符 `{{attach_id}}` `{{name}}` `{{company}}` `{{projects}}` `{{apiKey}}`） |
| `wecomChat` | 会话记录看板：连接本机企业微信聊天记录解析服务（默认 `http://127.0.0.1:8767`）。`readMode` 为 `auto` 时优先直读解析项目已同步的 JSON（`dataRoot` 可指向 `export/synced` 的上级目录，留空则自动找旁边的解析项目）。`groups` 为关注会话（群聊和单聊都算）。`watch` 为 AI 值班：间隔、回看窗口、模式（`auto` 自动提交待确认 / `review` 只进待人审 / `off` 关闭）、`skipDismissed`（点过「不上传」的申报书不再进入待审，默认开）。文件只走缓存 |
| `mysql` | 用户账号库（登录 / 会话 / 管理后台） |

规则：

- 独立网关**不得**误用顶层 Grok 密钥。
- 火山地址已是 `/api/v3`，不要再拼 `/v1`。
- 用户前端 `/api/config` 只下发 Gemini 模型与 `hasKey` 等状态，**不回传明文密钥、不展示 Grok / 火山 / 库地址**；管理员 `/api/config` 才返回完整模型配置。
- 论文密钥由导出系统管理员线下提供，写入 `papers.apiKey`；对接约定见仓库内 `论文api文档.md`。

## 2.7 能力

- **QM / HJ 模板自动识别**：`app/form_kind.py` 对照根目录 `QM.docx` / `HJ.docx` 特征与内置结构词，把申报书判为 QM（启明，Word）或 HJ（火炬，如佛山仙湖实验室，常为 Excel），贯穿预处理、库检索（`mode`）、章节规则与落盘
- **Word / Excel 申报书均可**：接受 `.docx / .docm / .wps / .xlsx / .xlsm / .xls` 与数字版 `.pdf`（扫描 PDF 拒绝）；写回时 Word 用 `apply_edits.py` 1:1 结构写入，Excel 用 `apply_excel.py` 按单元格改写、保留格式与 VBA（`.xls` 走本机 Excel COM）
- **意见文档可选**：不传意见时从申报书标注栏（Word 批注 / Excel 批注）自动抽取修改意见；批量模式下未配对到任何修改意见的申报书直接跳过——不套用通用条款、不创建任务
- **Gemini 单模型出计划**：分类与按章出计划只用 Gemini，计划表只保留「Gemini 修改意见」一列，可点「采用」写入「修改后」；对照表 / 前端文案同步为单模型口径
- **印刷栏位限字强约束**：以申报书印刷「限 N 字 / N 字以内」为最高优先级，覆盖规则包；`find` 命中「重要经历 / 主要技术能力 / 标志性成果」及企业情况「①业务领域～⑤产业链地位」等子栏时按占比拆限字，`enforce_edit_limits` 对超限 replace 先压缩再输出，剩余超限写入遗留事项「【表内限字】」
- **账号体系**：MySQL 存储用户（用户名 / 真实姓名 / 部门 / 角色 / 状态），PBKDF2-SHA256 密码，Cookie 会话 7 天；未登录访问页面跳 `/login`，API 返回 401
- **开放 API**：`/api/v1` 用 API Key 创建与查询任务（multipart 上传申报书 / 意见，可选 `autoApply` 自动写入）；管理后台发放、停用、删除密钥、查看完整 Key 与调用历史
- **数据隔离**：任务与批次记录提交人，普通用户只能看到自己的任务与日志，越权访问一律 404；历史无归属任务仅管理员可见；开放 API 每把密钥只能访问自己创建的任务
- **管理后台 `/admin`**：任务总览（统计卡 + 最近任务 + 产出下载 + 提交人）、新建任务入口、人员信息（角色 / 状态 / 重置密码 / 删除，保护最后一名管理员）、**开放 API**（发放 / 停用 / 删除 API Key、查看调用历史）、模型配置（Grok / Gemini / 火山可视化编辑，密钥留空不修改）、系统信息、**各群记录看板**（企业微信只读解析：按群看消息、从缓存下文件、用聊天记录定位当时修改任务、按日期窗拆申报书并挂上附近修改意见后上传）；右侧锚点菜单
- **任务深链**：打开任务后地址栏为 `/t/{任务id}`，刷新或分享可回到同一条；浏览器标签页标题不随任务切换
- **确认写入快照**：人工确认落盘成功后，把当时的 `output/` 拷到 `tasks/{id}/versions/{appliedAt}/`，之后重试不会盖掉这一版
- **缺附件检索 + 附件包**：意见点名缺护照 / 学历证明 / 工作证明 / 意向协议 / 论文全文 / 证件照 / 电子签 / 项目证明等时，**先按申报书编号在本机 `附件/{编号}/`（护照、工作经历等子目录）查找**，命中则给出本系统下载链接；本地没有再到人才库附件包、库 payload；仍没有则按编号/姓名检索**企业微信聊天记录**中的群文件（须解析服务 8767 在线，下载走缓存）。计划页与任务完成后均可下载
- **任务清单（系统改不了的附件）**：护照扫描件、学历/学位证明、工作经历证明/在职证明等无法写入申报书正文。意见要求更换扫描件，或更正证明上的**时间、日期、入职/离职、起止年限**等，一律进任务清单（先查本地附件，找不到再查人才库，再查聊天记录）。护照号码、工作经历表格按职务职责改写等正文栏仍走编辑计划，不当成附件任务。计划生成与确认写入均产出 `任务清单.docx`（并保留 `.md`），Word 内含本地 `file:///` 与系统代理下载链接
- **论文导出 API**：库内没有可下载论文时，按 `attach_id` 先 `GET /api/v1/talents/{id}`；无档或无 PDF 则作者检索并提交构建任务，再拉装订件与单篇 PDF，题录写入申报书论文栏
- **失败任务可重试**：任务列表 / 详情 / 计划页均可点「重试」，`POST /api/tasks/{id}/retry` 从预处理重新跑（记录重试次数）
- **输出可靠性**：对模型返回的 JSON 做容错解析（BOM、```json 围栏、字符串内裸控制字符）；任务完成后做终检限字并生成对照表与遗留事项
- 产出：`*_修改后.{同源扩展名}`、`*_备份.{同源扩展名}`、修改对照表（Markdown + Word）、遗留事项.md、**任务清单.docx**（有附件事项时）

## 管线

```
登录（MySQL 会话校验，普通用户仅见本人数据）
        ↓
提交申报书（自动识别 QM / HJ 模板）
  意见文档（可选；不传则读申报书标注栏批注）
  或：管理后台各群记录「拆解任务」→ 申报书 + 附近修改意见（群文本或文档）→ 写入任务列表
        ↓
预处理（Word / Excel 抽取；数字 PDF 先转 .docx；扫描 PDF 拒绝）
  切意见 / 切标注块 → 按模板章节分类（QM 六章 / HJ 九章）
        → 人才库 / 企业库检索（带 mode 过滤）
        → 缺附件检索（本机「附件」目录 → 人才库附件包 → 库 payload → 聊天记录群文件 → 论文 API（查档 / 作者检索 / 构建）；项目证明再走 CodeBuddy 联网检索 → 生成 API（来华前单位签发））
        → 注入填表须知 + 章节规则 + 库数据 + 附件链接
        → Gemini 按章出 edits / leftovers（思考中度，温度 0.1）
        → 合并去重、印刷限字压缩、写入附件下载遗留项
        → 系统改不了的附件（护照/学历证明/工作证明及证明上的时间等）→ 任务清单.docx
        → 人工逐条核对（Gemini 修改意见 / 修改后可编辑）
        → apply_edits / apply_excel 写回源文件（结构对齐、保留宏）
        → 终检限字、对照表、遗留事项、任务清单；缺失附件可下载
        → 确认写入快照 versions/{appliedAt}/（重试不覆盖历史版）
```

匹配规则（matcher v2）：编号 90 / 前缀 85 / 全名 100；弱 token 走 LLM 仲裁。`25xxxx` / `26xxxx` 视为日期码，不参与编号匹配。`is_app_content` 覆盖 QM / HJ 封面标记，HJ（Application Form / 实验室名称等）也能通过预检。

章节与规则包：

- **QM（启明，Word）**：基本信息、教育、工作、论文、项目、其他 → `rules/basic-info.md`、`education.md`、`work.md`、`papers.md`、`projects.md`
- **HJ（火炬，Word / Excel）**：关键申报信息、个人基本信息、教育、工作、学术荣誉、专长成果、工作设想、用人单位、其他 → `rules/hj-key.md`、`hj-profile.md`、`hj-education.md`、`hj-work.md`、`hj-honors.md`、`hj-expertise.md`、`hj-plan.md`、`hj-employer.md`

## 缺附件、任务清单与论文 API

当修改意见含「缺护照 / 缺少学历证明 / 未上传学位证 / 论文需附全文 / 缺论文 PDF / 缺证件照 / 电子签」等表述，或要求**更换扫描件、更正证明材料上的时间/日期**时：

1. 扫描意见与后续遗留事项，识别附件类型（护照 / 学历 / 工作证明 / 论文 / 证件照 / 电子签 / 项目证明等）
2. **本机优先**：按申报书编号在项目 `附件/{编号}/护照`、`附件/{编号}/工作经历` 等目录查找（文件名含「学历证明」即使放在护照夹也按学历归类）
3. 本地没有则按人才编号 `attach_id` 请求**人才库附件包**（按必交清单回填命中文件）
4. 附件包无果时在人才库、企业库 JSON 中查找带下载地址的文件（文件名或类型含护照、学历、论文等）
5. **聊天记录**：本地与人才库仍没有时，用申报书编号、姓名和「护照 / 学历证明 / 工作证明」等关键词检索企业微信解析服务；命中且文件名可归类的群文件写入任务清单（下载走 `/api/tasks/{id}/ext-files/{fid}`，后端从解析服务缓存取文件）
6. **论文**：库内无 PDF 时先 `GET /api/v1/talents/{attach_id}`；404 或无文件则 `POST /api/search` 按作者检索，把题录作为 `papers_json` 提交 `POST /api/v1/papers/jobs` 并轮询任务，再拉装订 PDF 与单篇 PDF。题录写入计划提示，供申报书「代表性论文」栏补写（引用数、影响因子未知留空）
7. **项目证明**：库内无文件时，用申报人姓名与**来华前工作单位**下的项目列表调用本机 `codebuddy -p`（`--permission-mode bypassPermissions`，`--output-format json`）联网检索立项批文 / 资助公示 / 官方 PDF；仍未命中则按 `projectProof.generate` 模板请求生成 API。无来华前雇主或与申报企业相同则跳过生成，不用申报企业签发
8. 计划 JSON 的 `attachments` 与遗留事项写入本系统链接：`/api/tasks/{任务id}/ext-files/{id}`  
   浏览器不接触上游密钥；下载由后端带 `X-API-KEY` / `X-Api-Key` 代拉；生成 API 未填写（含 `填入`）时跳过并在遗留事项注明
9. **任务清单**：下列事项**不能**通过改申报书正文完成，计划页展示清单，并生成 `任务清单.docx`（蓝字链接：本地文件 `file:///`，人才库与聊天记录走系统代理）
   - 护照 / 身份证明 / 学历证明 / 工作经历证明 / 在职证明等扫描件的更换、补传、不清晰
   - 工作证明、学历证明上的**起止时间、入职/离职日期、签发日期**等栏位更正
   - **不算**附件任务：护照号码、工作经历表格按职务职责/贡献改写、工作经历时间按年月填写（这些走正文编辑计划）

论文系统约定（详见 `论文api文档.md`）：

- 人才 ID 与汪伦 `attach_id` 一致；相对路径 `url` / `pdf_url` 需加 Base URL
- 查档：`GET /api/v1/talents/{id}`。无档或无 PDF 时：`POST /api/search` 作者检索 → `POST /api/v1/papers/jobs` 构建 → `GET /api/v1/jobs/{id}` 轮询
- 401 密钥错误；404 无该人（随后走检索构建，不再视为终态失败）

未配置 `papers.apiKey` 时，护照等仍可走人才库；论文遗留事项会提示「论文 API 未配置」。

## 版式与填表须知

- `find` 与 `replace` 换行次数必须一致；表格左栏标题与右栏正文不得并成一段；严禁把「引进企业基本情况」①业务领域～⑤产业链地位整栏写进同一条 replace（find 是哪一格就只改哪一格）
- 不得新增申报书没有的小标题；一次编辑只改锚点覆盖的那一块
- 字数按印刷「限 N 字 / N 字以内」，目标约上限的 80%～90%，**绝对不得超过上限**；【限字】与填表要求优先于章节规则包
- 除规定栏位外：不出现申报人姓名、企业名称；金额万元、一位小数
- 按申报书模板切章；HJ 申报书以印刷栏位（关键申报信息 / 个人基本信息 / 教育 / 工作 / 学术荣誉 / 专长成果 / 工作设想 / 申报单位）为界，不与 QM 六章混用

## 前端要点

- 计划表：用 / 编号 / 章节 / 意见条款 / 修改前（只读锚点）/ Gemini 修改意见 / 修改后（可编辑）；取消勾选＝放弃该条
- 未上传意见时提示已从标注栏提取条数；批量结果中未配对的书显示「跳过」
- 缺附件命中时计划页显示可下载清单；任务完成后在详情页再次展示缺失附件下载
- 系统改不了的附件（含工作证明时间等）在计划页 / 完成后展示**任务清单**，可下载 `任务清单.docx`；链接标明「本地附件」「人才库」或「聊天记录」
- 失败任务在列表 / 详情 / 计划页显示「重试」，从预处理重跑
- 打开任务后地址栏同步 `/t/{id}`，刷新停留在当前任务；标签页标题不变

## 安全

- 登录才能使用系统；普通用户仅能访问自己提交的任务（详情 / 计划 / 文件 / 附件全部校验归属）
- 对外开放 `/api/v1` 用独立 API Key（`X-Api-Key`），与网页会话无关；鉴权用哈希，管理员后台可查看明文；每把密钥只能访问自己创建的任务
- 初始管理员 `admin`，**首次登录后请立即在后台修改密码**
- 原件只读，确认前不改申报书（输出先写 `*_修改后` / `*_备份`）；群聊拆解只建到「待确认」，不自动调用写入
- 值班配置仅管理员。普通用户可在主页查看扫描日志、审核待审申报书，并手动扫描（冷却 60 秒）。会话文件只走企业微信本机/远端缓存，过期 CDN 链不当下载源
- 库与申报书都没有的事实写入 leftovers，禁止编造
- 密钥仅存本机 `config.json`（已 gitignore），用户前端只暴露 `hasKey` 与 Gemini 参数
- 模型配置修改与恢复默认仅限管理员
- 附件下载走任务内代理，不把上游 URL 和密钥交给浏览器

## 会话记录与 AI 值班

依赖本机企业微信解析服务（`wecomChat.baseUrl`，默认 `http://127.0.0.1:8767`）。同一会话在多台电脑上合并为一条，群聊和单聊都算。`readMode=auto` 时看板优先读已同步 JSON，不必整段走 HTTP。

| 能力 | 说明 |
|------|------|
| 看板 | 看时间、发送人、正文、文件；自动刷新不打断下载/预览。左侧 ★ 加入关注，供值班扫描 |
| 下文件 | `POST /api/wecom/files` 按各电脑 `copies` 查缓存；哪台打开过就从哪台取。系统消息里的 `tpdownloadmedia` 链会收成文件卡，不当成正文 |
| 定位申报书 | 文件卡「定位申报书」→ `POST /api/wecom/locate-task`：用姓名 / 文件名 / 编号 / 时间窗（当天、7 天、30 天）对任务打分，打开 `/t/{id}`，下载该任务修改后/备份，以及会话里那份原文件 |
| 拆解任务 | 聊天头「拆解任务」→ 规则拆解后调用现有 Gemini 协助定位申报书与修改意见 → 预览后上传。公司名 Word / PDF / WPS（含「有限公司」等、即使文件名没有「申报书」）视为申报书；资料清单、聘用意向书、唯一申报承诺不当申报书。修改意见可以是会话文本，也可以是系统支持的意见文档（含 `.wps`）。未设日期时默认最近 14 天 |
| 文件汇总 | 当前会话附件按人才材料类别归组；可定位到各电脑副本中的原文 |
| AI 解读 | 通读当前会话或关注群，列出申报书版本与修改意见绑定（时间窗 / 编号 / 语义），结果保存，不自动建任务 |
| AI 值班 | 按水位扫描关注会话的新消息。首次只记水位。模式 `review` 只进待人审；`auto` 在配对通过后提交待确认任务。扫描日志可点开 |
| 待人审 | 主页与后台列出申报书和识别到的修改意见。「上传任务」强制建成待确认任务；「不上传」移出列表。`skipDismissed` 打开时，这份申报书之后不再进入待审 |
| 立即扫描 | 普通用户主页可手动扫一轮，冷却 60 秒。值班开关、间隔、模型检测仅管理员 |
| 人工确认 | 上传或拆解之后仍走两阶段：生成计划 → 首页/深链核对 → 「确认无误，写入文件」。缺缓存的申报书无法创建；意见文档未缓存时仍建任务，并尝试从标注栏抽意见。老式 OLE 的 `.wps` 用本机 Word 抽文本 |
